# Protocol delta: 393 (1.13) → 404 (1.13.2)

Sources: wiki.vg Protocol History, Mojang version manifests, Conduit's
existing `ItemCodec` boundary (found earlier by a real 1.13 dropped-item
metadata rejection), and Prismarine/published packet-id tables.

## Summary

| Axis | Change |
| --- | --- |
| Protocol numbers | 393 → 401 (1.13.1) → 404 (1.13.2) |
| Packet id tables | **0 changed mappings** (derived codec inherits 393 ids) |
| Configuration state | none (both predate config phase) |
| Framing / VarInt / compression | unchanged |
| Handshake / status / login | unchanged field layouts |
| Play movement / chunks / dig / place | unchanged |
| **Slot (item stack) wire form** | **CHANGED** (the gameplay-critical delta) |

## Slot restructuring (1.13.2-pre1 → 404)

Direction: every packet that embeds the Slot datatype, both directions.

| Era | Layout |
| --- | --- |
| 393 / 401 | `itemId:i16` (`-1` = empty) `[ count:i8  nbt(NAMED) ]` |
| 404 | `present:bool` `[ itemId:VarInt  count:i8  nbt(NAMED) ]` |

Semantic meaning is unchanged: one inventory stack (or empty). Represented by
existing `SemanticItem`. No new semantic model required.

Affected high-priority packets (ids identical on both sides):

| Kind | Direction | State | Action |
| --- | --- | --- | --- |
| `PLAY_SET_CONTAINER_CONTENT` | S→C | PLAY | rematerialise slots via `ItemCodec` |
| `PLAY_SET_CONTAINER_SLOT` | S→C | PLAY | rematerialise slot |
| `PLAY_CLICK_WINDOW` | C→S | PLAY | rematerialise clicked/carried slot; preserve action number |
| `PLAY_CREATIVE_SLOT` | C→S | PLAY | rematerialise slot |
| `PLAY_ENTITY_EQUIPMENT` | S→C | PLAY | rematerialise item (still one slot per packet) |
| `PLAY_SET_ENTITY_METADATA` | S→C | PLAY | rematerialise Slot-typed fields only; indices/types unchanged |

Cosmetic / complex Slot carriers (dropped rather than guessed):

| Kind | Reason |
| --- | --- |
| `PLAY_DECLARE_RECIPES` | embeds many Slots; recipe book not required for core play |
| `PLAY_UPDATE_ADVANCEMENTS` | icon Slots |
| `PLAY_TRADE_LIST` | merchant offer Slots |

## What can be reused directly

Everything that does not embed Slot: login, join game, respawn, chunks, block
changes, movement, digging, placement (cursor floats only), keepalive, chat,
plugin messages, health, experience, scoreboard framing, entity spawn/destroy
(type ids unchanged within 1.13.x), attributes (same era).

## Architecture choice

Not a pair-specific mega-translator. `Protocol393To404Translator` is a small
delta adapter: identify by `PacketKind`, rematerialise Slot-bearing bodies
through existing codecs, opaque-forward the rest. Packet ids are never offset.
